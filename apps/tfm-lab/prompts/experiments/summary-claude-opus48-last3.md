## Methodology / isolation

- Each experiment ID was generated by a **separate, freshly spawned Claude Opus 4.8 (Medium)
  subagent**. No subagent generated more than one experiment, and no two experiment outputs share a
  continuous chat context — satisfying the mandatory per-experiment context-isolation rule.
- Each subagent was given only its own `input.md` path and instructed to write the raw DSL to its
  own `output.dsl` (no fences, no commentary). Outputs are preserved verbatim; no manual edits.
- For the SYSV31 folders, the `input.md` stubs already existed (pending) and were filled in place;
  the SYSV4/SYSV5 folders were scaffolded fresh in this batch.

## Warnings / limitations

- **Model substitution:** Claude Opus 4.8 (Medium) was used instead of Gemini 3.5 Flash Thinking,
  per instruction. Folder names, `provider`, `modelLabel`, `systemPromptVersion`, and
  `executionSetting` reflect this.
- **Scope:** only SYN013–SYN015 (the hard/stress processes), under SYSV31, SYSV4 and SYSV5
  (27 experiments), not the full corpus matrix.
- **Reasoning mode:** the Agent SDK subagent path does not expose a literal "Medium reasoning"
  toggle; `OPUS_4_8_MEDIUM` / "Medium" is recorded as the intended setting label for traceability,
  consistent with the pre-existing SYSV31 Opus 4.8 Medium stubs.
- **Transient session limit during generation (V4/V5 batch):** the final SYN015 V5 batch initially
  hit a session limit on the agent-reply step; most outputs had already been written, and the one
  genuinely-missing output was regenerated by a fresh subagent after the limit reset. All outputs
  are present and non-empty.
- **Observational only:** generated DSL was checked for presence and absence of markdown fences, but
  not corrected. Structural validity is assessed later by the headless render/evaluation pipeline
  and/or the TFM app.
